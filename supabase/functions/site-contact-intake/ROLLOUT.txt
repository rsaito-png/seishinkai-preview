1. Apply the migration yourself (review the SQL first)
   File: supabase/functions/site-contact-intake/schema.sql
   It creates schema site_contact, tables inquiries and rate_buckets,
   enables and forces RLS, and grants nothing to anon or authenticated.
   Do not add site_contact to the Data API exposed schemas.
   Do not add a SELECT policy.

2. Deploy the function with verify_jwt false
   Directory: supabase/functions/site-contact-intake/
   Entrypoint: index.ts
   Files that must ship together: index.ts, handler.mjs, shared.mjs,
   notice.mjs, pg_store.mjs.
   The function reads SUPABASE_DB_URL, which hosted Edge Functions provide.
   Confirm the gateway setting verify_jwt is false (supabase/config.toml
   in this website repo). A visitor has no JWT.

3. Set secrets in the Supabase function environment. Do not commit them.
   CONTACT_INTAKE_ENABLED=1
   CONTACT_MAIL_TRANSPORT=https-json
   CONTACT_MAIL_URL=https://...     existing mail API you already use
   CONTACT_MAIL_TOKEN=...           bearer token for that API
   CONTACT_MAIL_FROM=...            verified sender, no newlines
   CONTACT_RETRY_SECRET=...         long random string for the retry call
   CONTACT_IP_PEPPER=...            optional; hashes IP addresses before storage

   https-json is only a slot. This repository does not call a provider
   until those values exist. The POST body is JSON:
   {"to":"rsaito@psr-seishinkai.org","from":"<CONTACT_MAIL_FROM>","subject":"【星心会】ウェブサイトからの相談","text":"<notice>"}
   There is no Cc, Bcc, or reply to the person who submitted the form.

   If you do not already have an HTTPS mail API and a verified From,
   stop here. Leave the public switch off.

4. Retry failed notifications (does not create another lead)
   POST the function with header x-contact-retry-secret set to the secret.
   Schedule that call from pg_cron only after the secret is in Vault under
   the name contact_retry_secret. Read it at call time. Do not put the
   secret in SQL text. The cron should not run until step 3 is done.
   Rows with notification_status pending or failed stay in
   site_contact.inquiries. sent is a separate state. A failed send is not
   reported as notified.

5. Only then edit assets/contact-config.js
   enabled: true
   endpoint: "https://zvrardoyxocmqhvyddnf.supabase.co/functions/v1/site-contact-intake"
   Deploy the static file. Until this edit, the button on /contact/ stays disabled.

6. GA4 admin (required; code cannot turn this off by itself)
   Property for G-XVX8LZ4DXC.
   Admin > Data collection and modification > Data streams > the web stream.
   Enhanced measurement > turn off Form interactions.
   Also open the Google tag settings > Manage automatic event detection >
   turn off Form interactions, or Google Ads can still receive form_submit.
   Do not mark the automatic event form_submit as a key event.
   Mark only the custom event contact_inquiry_accepted.
   That event is sent from the browser only after the JSON says
   stored and lead_event, and it carries method=server_receipt and
   form_id=contact-intake. It has no name, email, or message.
   A duplicate, a rejection, a rate limit, a storage error, or a mock
   does not set lead_event.
